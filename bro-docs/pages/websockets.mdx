# WebSockets (Socket.io)

Real-time capabilities are usually a massive pain to wire up alongside an Express REST API. Not in `bro.js`. WebSockets are treated as a first-class citizen.

## Setup

Enable and configure your sockets in `bro.config.js`:

```javascript
export default defineConfig({
  sockets: async (io, db) => {
    // This runs once on boot
    io.on('connection', (socket) => {
      console.log('🟢 Client connected:', socket.id);
      
      socket.on('ping', () => {
        socket.emit('pong');
      });
    });
  }
});
```

## Emitting from Routes

The `io` instance is injected into every single API route context. This means you can broadcast real-time events the exact millisecond a database update finishes.

```javascript
import { defineRoute } from 'bro-framework';

export default defineRoute({
  handler: async ({ body, db, io }) => {
    // 1. Save data
    await db.collection('messages').insertOne(body);
    
    // 2. Alert all connected clients instantly!
    io.emit('new_message', body);
    
    return { success: true };
  }
});
```

## Auto-Scaling with Redis

If you run multiple instances of your API behind a load balancer, standard WebSockets will fail because clients might connect to different nodes. 

With `bro.js`, just set `redisUrl` in your `bro.config.js`. The engine will automatically detect Redis and seamlessly configure `@socket.io/redis-adapter` for you. Your real-time events will instantly broadcast across your entire cluster with absolutely zero boilerplate!
